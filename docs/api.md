# API reference

The Express API is mounted under `/api`. In development it runs on
`http://localhost:3001` and the Vite dev server proxies `/api/*` to it, so the
browser only ever talks to `http://localhost:5173`.

Every `/api` response carries `Cache-Control: no-store` and
`X-Content-Type-Options: nosniff`, and CORS is enabled for all origins.
Request bodies are parsed as JSON with a 256 KB limit.

## The note resource

```json
{
  "id": "e79a5521-e8c7-4fd0-a8a5-03167efecf30",
  "title": "قائمة التسوق",
  "body": "حليب، خبز",
  "createdAt": "2026-08-20T06:44:20.397Z",
  "updatedAt": "2026-08-20T06:44:20.397Z"
}
```

| Field | Type | Notes |
| --- | --- | --- |
| `id` | string | UUID v4, generated by the server |
| `title` | string | Trimmed, required, 1–200 characters |
| `body` | string | Trimmed, optional, at most 8,000 characters (`""` when omitted) |
| `createdAt` | string | UTC ISO-8601 timestamp |
| `updatedAt` | string | UTC ISO-8601 timestamp, equals `createdAt` until the note is edited |

Non-string `body` values are stored as `""` rather than rejected. A note is
considered edited (and the UI shows an "edited" marker) when `updatedAt`
differs from `createdAt`.

## Endpoints

| Method | Path | Success | Description |
| --- | --- | --- | --- |
| `GET` | `/api/health` | `200` | Liveness plus persistence status |
| `GET` | `/api/notes` | `200` | All notes, newest `updatedAt` first |
| `GET` | `/api/notes/export` | `200` | Download all notes as JSON or Markdown |
| `GET` | `/api/notes/:id` | `200` | A single note |
| `POST` | `/api/notes` | `201` | Create a note |
| `PUT` | `/api/notes/:id` | `200` | Partially update a note |
| `DELETE` | `/api/notes/:id` | `204` | Delete a note |

`/api/notes/export` is matched before `/api/notes/:id`, so `export` is a
reserved id.

### GET /api/health

```console
$ curl -s localhost:3001/api/health
{"status":"ok","persist":"ok","uptime":18.476324137}
```

`persist` is `ok`, `degraded`, or `unavailable`, and `status` mirrors it. See
[Persistence states](#persistence-states).

### GET /api/notes

Returns an array sorted by `updatedAt`, newest first.

```console
$ curl -s localhost:3001/api/notes
[{"id":"8b200071-…","title":"Shopping list","body":"","createdAt":"…","updatedAt":"…"}]
```

Returns `503` while the data file is unreadable, so a load failure never looks
like an empty notes list.

### GET /api/notes/export

| Query | Values | Default |
| --- | --- | --- |
| `format` | `json`, `md` (`markdown` is accepted as an alias) | `json` |

The response is an attachment named `notes-YYYY-MM-DD.<format>`:

```console
$ curl -sD - -o notes.md 'localhost:3001/api/notes/export?format=md'
HTTP/1.1 200 OK
Content-Disposition: attachment; filename="notes-2026-08-20.md"
Content-Type: text/markdown; charset=utf-8
```

The JSON export wraps the notes in an envelope:

```json
{
  "exportedAt": "2026-08-20T06:44:20.515Z",
  "count": 2,
  "notes": [ /* … */ ]
}
```

The Markdown export writes one `##` section per note (with `#` and `\`
escaped in headings), followed by the note body and an id/created/updated
list, separated by `---` rules. An unsupported `format` returns `400` with
`{"error":"format must be json or md"}`.

### POST /api/notes

```console
$ curl -s -X POST localhost:3001/api/notes \
    -H 'Content-Type: application/json' \
    -d '{"title":"Shopping list"}'
{"id":"8b200071-…","title":"Shopping list","body":"","createdAt":"2026-08-20T06:44:20.413Z","updatedAt":"2026-08-20T06:44:20.413Z"}
```

`title` is required; `body` is optional.

### PUT /api/notes/:id

A partial update: omitted fields keep their current values.

```console
$ curl -s -X PUT localhost:3001/api/notes/e79a5521-… \
    -H 'Content-Type: application/json' \
    -d '{"body":"حليب، خبز، بيض"}'
{"id":"e79a5521-…","title":"قائمة التسوق","body":"حليب، خبز، بيض","createdAt":"2026-08-20T06:44:20.397Z","updatedAt":"2026-08-20T06:44:20.428Z"}
```

A request that changes nothing returns the existing note without touching
`updatedAt` or writing to disk. A request that carries neither `title` nor
`body` returns `400` with `{"error":"title or body is required"}`.

### DELETE /api/notes/:id

Returns `204` with an empty body, or `404` if the note is already gone.

## Errors

Errors are always JSON: `{"error":"<message>"}`.

| Status | When | Body |
| --- | --- | --- |
| `400` | Missing title | `{"error":"title is required"}` |
| `400` | Title over 200 characters | `{"error":"title must be at most 200 characters"}` |
| `400` | Body over 8,000 characters | `{"error":"body must be at most 8000 characters"}` |
| `400` | `PUT` with no fields | `{"error":"title or body is required"}` |
| `400` | Malformed JSON | `{"error":"invalid request body"}` |
| `400` | Bad export format | `{"error":"format must be json or md"}` |
| `404` | Unknown note id | `{"error":"note not found"}` |
| `404` | Unknown `/api` route | `{"error":"not found"}` |
| `413` | Request body over 256 KB | `{"error":"request body too large"}` |
| `503` | Data file cannot be read or safely rewritten | see below |
| `500` | Unexpected failure | `{"error":"internal server error"}` |

## Persistence states

Notes live in `server/data/notes.json` (override with `NOTES_DATA_FILE`). The
store loads the file once at startup and never overwrites a file it could not
fully understand, so a bad file degrades the API instead of destroying data.

| `persist` | Cause | Reads | Writes |
| --- | --- | --- | --- |
| `ok` | File loaded, or absent (fresh install) | `200` | `200`/`201`/`204` |
| `degraded` | Some records were skipped (empty title, over-length field, unparseable date, duplicate id) | `200` with the valid notes | `503 {"error":"notes data file has invalid records; refusing to overwrite it"}` |
| `unavailable` | File unreadable, not JSON, or not an array | `503 {"error":"notes data file could not be loaded"}` | `503 {"error":"notes data file could not be loaded; refusing to overwrite it"}` |

Recover by fixing or removing the data file and restarting the API. Writes are
atomic — the store writes `notes.json.<pid>.tmp` and renames it over the real
file — and a failed write rolls the in-memory change back so the API and disk
never disagree.

## Serving the built UI

When `client/dist/index.html` exists, the API also serves the SPA:
hashed files under `assets/` get `Cache-Control: public, max-age=31536000,
immutable`, extensionless `GET`/`HEAD` paths fall back to `index.html` with
`no-store`, and any other missing file returns `404` instead of the HTML shell.
