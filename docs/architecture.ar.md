# البنية المعمارية ودليل التطوير

[العودة إلى README العربية](../README.ar.md)

## نظرة عامة

المستودع مقسوم إلى مساحتَي عمل npm مستقلتين تحت جذر واحد:

```
.
├── client/                  # واجهة React + Vite + TypeScript
│   ├── src/
│   │   ├── main.tsx         # نقطة الدخول: تركيب <App /> في الصفحة
│   │   ├── App.tsx          # المكوّن الرئيسي: النموذج والقائمة والبحث والتصدير
│   │   ├── api.ts           # عميل HTTP مع تحقق من شكل الاستجابات
│   │   ├── exportNotes.ts   # توليد ملفات JSON/Markdown وتنزيلها من المتصفح
│   │   ├── i18n.ts          # كشف اللغة، نصوص الواجهة (عربي/إنجليزي)، توحيد نص البحث
│   │   └── index.css        # الأنماط
│   └── vite.config.ts       # خادم التطوير، وكيل /api، إعداد Vitest
├── server/
│   ├── src/
│   │   ├── index.ts         # نقطة الدخول: قراءة البيئة وتشغيل الخادم
│   │   ├── app.ts           # إنشاء تطبيق Express والمسارات ومعالجة الأخطاء
│   │   ├── notesStore.ts    # مخزن الملاحظات مع الحفظ في ملف JSON
│   │   └── exportNotes.ts   # توليد ملفات التصدير على الخادم
│   └── data/notes.json      # ملف البيانات (يُنشأ عند أول كتابة، خارج git)
├── docs/                    # هذا التوثيق
├── eslint.config.js         # إعداد ESLint مشترك (flat config)
└── package.json             # مساحات العمل والأوامر العلوية
```

## الخادم (`server/`)

### `index.ts` — نقطة الدخول

يقرأ `PORT` و `HOST` و `NOTES_DATA_FILE` من البيئة (مع التحقق من صحة
المنفذ)، وينشئ `NotesStore` مرتبطاً بملف البيانات، ثم يشغّل التطبيق.
إذا وُجد بناء العميل في `client/dist/index.html` يقدَّم كملفات ثابتة —
هكذا يخدم `npm start` الواجهة والـ API معاً من منفذ واحد.

### `app.ts` — التطبيق والمسارات

`createApp(store, options)` دالة مصنع تُنشئ تطبيق Express — تستقبل
المخزن حقناً للاعتماديات كي تعمل الاختبارات على مخزن في الذاكرة. أهم
النقاط:

- ترويسات `no-store` و `nosniff` على كل مسارات `/api`.
- مسار `/api/notes/export` معرَّف قبل `/api/notes/:id` كي لا تُفسَّر
  كلمة `export` معرّفَ ملاحظة.
- معالج أخطاء مركزي يترجم `ValidationError` إلى `400` و `PersistError`
  إلى `503`، ويحوّل أخطاء body-parser (JSON غير صالح `400`، جسم كبير
  `413`) إلى JSON موحّد.
- عند تقديم الملفات الثابتة: أصول `assets/` المجزّأة تُخزَّن مؤقتاً لعام
  كامل (immutable)، وأي مسار GET بلا امتداد يعود إلى `index.html`
  (توجيه SPA)، بينما الملفات ذات الامتداد المفقودة تعيد `404` ولا تسقط
  على `index.html`.

### `notesStore.ts` — المخزن والمتانة

`NotesStore` يحتفظ بالملاحظات في `Map` بالذاكرة، ويحفظها اختيارياً في
ملف JSON. قواعد التصميم:

- **بلا مسار ملف = ذاكرة فقط**: الاختبارات تنشئ المخزن بلا `persistPath`
  فتبقى معزولة.
- **كتابة ذرّية**: يُكتب ملف مؤقت باسم يتضمن رقم العملية (`.pid.tmp`)
  ثم `rename` فوق الملف الأصلي.
- **تثبيت أو تراجع**: كل عملية تعديل تنفَّذ في الذاكرة أولاً ثم تُحفظ؛
  إن فشل الحفظ يُستدعى تراجع (rollback) يعيد الحالة السابقة ويُرمى
  `PersistError` (تصبح `503`).
- **عدم استبدال ملف مشبوه**: إذا فشل التحميل أو تخطّى سجلات غير صالحة
  يُرفع علم `loadFailed` وتُرفض كل الكتابات حتى لا يُمحى الملف الأصلي.
  الحالة تُبلَّغ عبر `persistStatus()`‏: `ok` أو `degraded` (بعض السجلات
  صالحة) أو `unavailable` (لا شيء حُمّل).
- **توحيد التواريخ**: عند التحميل تُحوَّل `createdAt` و `updatedAt` إلى
  ISO-8601 بتوقيت UTC، وتُرفض السجلات ذات التواريخ غير القابلة للتحليل.

ملاحظة تشغيلية: أمر `npm run dev` في الخادم يستعمل `tsx watch` مع
استثناء مجلد `data/` وملفات `*.tmp`، فحفظ ملاحظة لا يعيد تشغيل الخادم.

### `exportNotes.ts` — التصدير من الخادم

يحلّل معامل `format` (يقبل `json` و `md` و `markdown`، والفراغ يعني
`json`)، ويولّد اسم الملف `notes-YYYY-MM-DD.ext` ومحتواه ونوعه. عناوين
Markdown تُهرَّب فيها أحرف `#` و `\` كي لا تكسر بنية المستند.

## العميل (`client/`)

### `App.tsx` — المكوّن الرئيسي

مكوّن واحد يدير كل الحالة عبر خطافات React (بلا مكتبة حالة خارجية):

- **التحميل الأولي مع إعادة محاولة**: عند الإقلاع يعيد المحاولة حتى 8
  مرات بتأخير متزايد إذا فشل الاتصال (يغطي سباق إقلاع الخادم مع خادم
  Vite في `npm run dev`)، ويعرض زر «إعادة المحاولة» عند الفشل النهائي.
- **إنشاء وتعديل بنموذج واحد**: النقر على «تعديل» يملأ النموذج ويحوّل
  الزر إلى «حفظ». التعديلات غير المحفوظة محمية بتأكيد قبل التبديل أو
  الإلغاء (زر أو مفتاح Escape) وبتحذير `beforeunload` قبل إغلاق الصفحة.
- **قفل التزامن**: مرجع `inFlightRef` وأعلام `saving`/`deletingId` تمنع
  الطلبات المتوازية والنقر المزدوج.
- **البحث**: ترشيح محلي فوري عبر `normalizeForSearch` (انظر i18n أدناه).
  الملاحظة قيد التعديل تبقى ظاهرة حتى لو لم تطابق البحث.
- **معالجة 404 أثناء التعديل**: إذا حُذفت الملاحظة من جهة أخرى أثناء
  تعديلها يُحوَّل النموذج إلى وضع الإنشاء كي لا يضيع ما كتبه المستخدم.
- **التصدير**: يصدّر الملاحظات المطابقة للبحث الحالي (وليس الكل بالضرورة)
  من بيانات العميل مباشرة، دون طلب إلى الخادم.

### `api.ts` — عميل HTTP دفاعي

يغلّف `fetch` مع `cache: "no-store"`، ويرمي `ApiError` يحمل رمز الحالة
ورسالة الخادم. الأهم: يتحقق من شكل كل استجابة (`parseNote` /
`parseNotes`) فيتجاهل السجلات المشوهة ويزيل التكرارات ويعيد الترتيب،
ويرمي خطأ إذا كانت الاستجابة كلها غير صالحة.

### `i18n.ts` — اللغة والبحث

- `detectLocale()` يقرأ لغة المتصفح ويعيد `ar` أو `en`. عند العربية
  يضبط `App` سمتَي `lang="ar"` و `dir="rtl"` على عنصر `<html>`.
- كائن `copy` يحوي كل نصوص الواجهة باللغتين.
- `normalizeForSearch()` يوحّد النص للبحث: يخفض الحالة، يزيل التشكيل
  والتطويل والحركات اللاتينية، يوحّد أشكال الألف (أ إ آ ٱ → ا) والهمزة
  على الواو (ؤ → و) وأشكال الياء (ئ ى ی → ي) والكاف الفارسية (ک → ك)
  والتاء المربوطة (ة → ه)، ويحوّل الأرقام العربية المشرقية والفارسية
  إلى لاتينية، ويطوي المسافات المتكررة.

### `vite.config.ts` — خادم التطوير والوكيل

يشغّل Vite على المنفذ `5173` (strict) ويمرّر `/api` إلى
`VITE_API_TARGET` (افتراضياً `http://127.0.0.1:3001`). إذا كان الخادم
متوقفاً يعيد الوكيل `502` بصيغة JSON بدلاً من قطع الاتصال، فيعرض
العميل رسالة «تعذر الوصول» المفهومة. الإعداد نفسه يضم تهيئة Vitest
(بيئة jsdom مع Testing Library).

## الاختبارات

- **الخادم**: Vitest مع Supertest. `app.test.ts` يختبر المسارات
  والتحقق ورموز الأخطاء، و `notesStore.test.ts` يختبر الحفظ والتراجع
  وحالات الملف التالف، و `exportNotes.test.ts` يختبر صيغ التصدير.
- **العميل**: Vitest مع jsdom و Testing Library. `App.test.tsx` يختبر
  التدفقات (إنشاء، تعديل، حذف، بحث، أخطاء)، و `api.test.ts` يختبر
  التحقق من الاستجابات، و `i18n.test.ts` يختبر كشف اللغة وتوحيد البحث.

شغّل الكل من الجذر:

```bash
npm test           # جميع الحزم
npm run typecheck  # فحص الأنواع
npm run lint       # ESLint
```

## التكامل المستمر (CI)

يعمل سير عمل GitHub Actions (`.github/workflows/ci.yml`) على كل دفعة
وطلب سحب نحو `main`، على Node ‏20 و 22، بالترتيب: تثبيت (`npm ci`) ثم
فحص الأنواع ثم lint ثم الاختبارات ثم البناء.
