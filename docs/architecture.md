# المعمارية · Architecture

تطبيق الملاحظات مساحة عمل npm واحدة فيها حزمتان: عميل Vite/React وخادم Express. في التطوير يعملان كعمليتين؛ في الإنتاج يبني العميل إلى ملفات ثابتة ويقدّمها الخادم إن وُجد `client/dist/index.html`.

```
المتصفح ──► Vite :5173 ──proxy /api──► Express :3001 ──► NotesStore ──► notes.json
                │                         │
                └── SPA (React)            └── في الإنتاج: ملفات client/dist
```

## العميل (`client/`)

| ملف | الدور |
| --- | --- |
| `src/main.tsx` | نقطة الدخول وReact StrictMode |
| `src/App.tsx` | الواجهة: قائمة، نموذج، بحث، تصدير، تعديل/حذف |
| `src/api.ts` | عميل REST مع التحقق من شكل الملاحظة |
| `src/exportNotes.ts` | بناء ملف JSON/Markdown وتنزيله في المتصفح |
| `src/i18n.ts` | كشف اللغة، النصوص، وتطبيع البحث |
| `index.html` | يضبط `lang` و`dir` و`document.title` قبل تحميل React لتفادي وميض الاتجاه |

سلوك مهم في الواجهة:

- إعادة المحاولة عند فشل التحميل الأولي (أخطاء شبكة/`502`/`504`) حتى لا تفشل الواجهة إذا تأخّر الخادم عن Vite.
- تأكيد قبل الحذف، وقبل تجاهل تعديلات غير محفوظة، وتحذير `beforeunload` عند وجود تغييرات.
- `Escape` يلغي التعديل (مع التأكيد إن لزم).
- الحقول `dir="auto"` حتى تختلط العربية والإنجليزية بشكل صحيح داخل البطاقة.
- التصدير من الواجهة يشمل نتائج البحث الحالية فقط.

## الخادم (`server/`)

| ملف | الدور |
| --- | --- |
| `src/index.ts` | المنفذ، المضيف، مسار ملف البيانات، وتقديم الملفات الثابتة إن وُجدت |
| `src/app.ts` | مسارات REST، CORS، JSON، أخطاء التحقق/الحفظ، SPA fallback |
| `src/notesStore.ts` | الحالة في الذاكرة + الحفظ الذري على القرص |
| `src/exportNotes.ts` | نفس صيغ التصدير التي يستخدمها العميل تقريباً |

في الإنتاج:

- الأصول تحت `/assets/` تأخذ `Cache-Control` طويل و`immutable`.
- `index.html` لا يُخزَّن (`no-store`).
- مسار فيه امتداد ملف (مثل `/favicon.ico` المفقود) يعيد `404` بدل `index.html`.

مراقبة التطوير (`tsx watch`) تستثني `server/data` حتى لا تعيد تشغيل الخادم عند حفظ ملاحظة.

## الحفظ على القرص

المسار الافتراضي: `server/data/notes.json` (من مجلد الخادم المُجمَّع: `../data/notes.json`). يمكن تجاوزه بـ `NOTES_DATA_FILE`.

بدون مسار حفظ (كما في معظم الاختبارات) يبقى المخزن في الذاكرة فقط.

آلية الكتابة:

1. إنشاء المجلد إن لزم.
2. كتابة JSON منسّق إلى ملف مؤقت `{path}.{pid}.tmp`.
3. `rename` فوق الملف النهائي (عملية ذرية على نفس نظام الملفات).
4. عند الفشل: حذف المؤقت، وإرجاع الحالة في الذاكرة كما كانت، ثم `503`.

عند التحميل:

- ملف غير موجود: بداية فارغة سليمة.
- JSON ليس مصفوفة، أو قراءة/تحليل فاشل: `unavailable`، ولا يُكتب فوق الملف.
- بعض العناصر باطلة (عنوان فارغ، طول زائد، تاريخ غير صالح، `id` مكرر): تُتخطى، الحالة `degraded`، والكتابة مرفوضة حتى يُصلح الملف.
- التواريخ تُحوَّل إلى ISO-8601 UTC حتى تُرتَّب شارات «معدّلة» بشكل متسق.

## البحث واللغة

`detectLocale()` تعتبر اللغة عربية إذا كانت `ar` أو تبدأ بـ `ar-`.

`normalizeForSearch()` يوحّد النص قبل المقارنة:

- تفكيك Unicode وإزالة التشكيل اللاتيني والعربي والكشيدة.
- `أ إ آ ٱ` → `ا`، `ؤ` → `و`، `ئ ى ی` → `ي`، `ک` → `ك`، `ة` → `ه`.
- الأرقام العربية المشرقية `٠-٩` والفارسية `۰-۹` إلى `0-9`.
- طي المسافات وحالة الأحرف.

لذلك يطابق البحث «الف» مع «ألف»، و«123» مع «١٢٣».

## الاختبارات

Vitest على العميل (jsdom + Testing Library) وعلى الخادم (Supertest ضد `createApp` بدون شبكة). أوامر الجذر تشغّل المساحتين عبر npm workspaces. CI على GitHub Actions يفحص Node 20 و22: تثبيت، أنواع، lint، اختبارات، ثم البناء.
