# تطبيق الملاحظات

[English](README.md) | **العربية**

تطبيق مبدئي صغير كامل المكدس يُستخدم لتهيئة تجربة التطوير في هذا المستودع.
يتكوّن من مساحتَي عمل (workspaces):

- **`client/`** — تطبيق صفحة واحدة مبني بـ React و Vite و TypeScript.
- **`server/`** — واجهة REST مبنية بـ Express و TypeScript مع حفظ الملاحظات في ملف.

أثناء التطوير يمرّر العميل طلبات `‎/api/*‎` إلى الخادم عبر وكيل (proxy)،
لذا يعمل الاثنان معاً وتتعامل مع عنوان واحد فقط.

للتوثيق التفصيلي راجع:

- [مرجع واجهة برمجة التطبيقات (API)](docs/api.ar.md)
- [البنية المعمارية ودليل التطوير](docs/architecture.ar.md)

## المتطلبات المسبقة

- Node.js بإصدار `20` أو أحدث (طُوِّر على Node 22)
- npm بإصدار `10` أو أحدث

## البدء السريع

```bash
npm install        # تثبيت اعتماديات جميع مساحات العمل
npm run dev        # تشغيل الواجهة الخلفية (المنفذ 3001) والعميل (المنفذ 5173) معاً
```

ثم افتح http://localhost:5173 وأنشئ ملاحظة.

في وضع الإنتاج يقدّم الخادم أيضاً ملفات العميل المبنيّة:

```bash
npm run build
npm start          # http://localhost:3001 (الواجهة الخلفية + واجهة المستخدم)
```

## الأوامر الشائعة

| الأمر | الوصف |
| --- | --- |
| `npm run dev` | تشغيل العميل والخادم معاً مع إعادة تحميل تلقائية |
| `npm run dev:server` | تشغيل واجهة Express فقط على المنفذ `3001` |
| `npm run dev:client` | تشغيل خادم تطوير Vite فقط على المنفذ `5173` |
| `npm test` | تشغيل جميع حزم الاختبارات (Vitest) |
| `npm run typecheck` | فحص الأنواع في جميع مساحات العمل |
| `npm run lint` | فحص كامل المستودع بـ ESLint |
| `npm run build` | بناء الخادم والعميل للإنتاج |
| `npm start` | تقديم الواجهة الخلفية وواجهة المستخدم المبنيّة على المنفذ `3001` |

## واجهة برمجة التطبيقات (API)

ملخّص سريع — التفاصيل الكاملة مع أمثلة في [مرجع API](docs/api.ar.md):

| الطريقة | المسار | الوصف |
| --- | --- | --- |
| `GET` | `/api/health` | فحص الصحة (`persist`:‏ `ok` أو `degraded` أو `unavailable`) |
| `GET` | `/api/notes` | قائمة الملاحظات (الأحدث أولاً) |
| `GET` | `/api/notes/export` | تنزيل جميع الملاحظات (`?format=json` أو `md`) |
| `GET` | `/api/notes/:id` | جلب ملاحظة واحدة |
| `POST` | `/api/notes` | إنشاء ملاحظة `{ title, body? }` |
| `PUT` | `/api/notes/:id` | تحديث جزئي لملاحظة `{ title?, body? }` |
| `DELETE` | `/api/notes/:id` | حذف ملاحظة |

القواعد الأساسية:

- الحد الأقصى للعنوان 200 حرف وللنص 8000 حرف. أي JSON غير صالح أو عنوان
  مفقود يعيد الرمز `400`، والمسارات المجهولة تحت `/api` تعيد `404` بصيغة JSON.
- `PUT` تحديث جزئي: الحقول غير المرسلة تحتفظ بقيمها الحالية.
- تُحفظ الملاحظات في `server/data/notes.json` (يمكن تغييره عبر متغيّر البيئة
  `NOTES_DATA_FILE`) فتبقى بعد إعادة تشغيل الخادم. الكتابة ذرّية
  (ملف مؤقت ثم إعادة تسمية)، وفشل الكتابة على القرص يعيد `503` مع التراجع
  عن التغيير في الذاكرة.
- الملف التالف أو غير القابل للقراءة لا يُستبدل أبداً؛ عندها تعيد قائمة
  الملاحظات `503` بدلاً من قائمة فارغة. السجلات غير الصالحة تُتخطى:
  يبلّغ فحص الصحة `degraded`، وتبقى القراءة ممكنة للملاحظات الصالحة،
  بينما تعيد عمليات الكتابة `503` حتى يُصلح الملف.
- الطوابع الزمنية المحمّلة تُوحَّد إلى صيغة ISO-8601 بتوقيت UTC كي يبقى
  الترتيب وعلامة «معدّلة» صحيحَين حتى مع صيغ مختلطة.

## واجهة المستخدم

- تتبع الواجهة لغة المتصفح تلقائياً، وتدعم العربية مع اتجاه من اليمين
  إلى اليسار (RTL) بالكامل.
- بحث فوري يتعامل مع أشكال الألف والتشكيل والهمزة على الواو والياء
  والياء والكاف الفارسيتين والأرقام العربية المشرقية والحروف اللاتينية
  المشكولة والمسافات الزائدة.
- تأكيد قبل الحذف وقبل تجاهل التعديلات غير المحفوظة.
- تصدير الملاحظات الظاهرة إلى JSON أو Markdown مباشرة من المتصفح.
