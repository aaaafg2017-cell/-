# تطبيق الملاحظات

[English](README.md) · [واجهة البرمجة](docs/api.ar.md) · [البنية](docs/architecture.ar.md)

تطبيق ملاحظات كامل المكدس صغير يُستخدم كأساس لهذا المستودع. يتكون من مساحتي عمل:

- **`client/`** — واجهة React + Vite + TypeScript.
- **`server/`** — واجهة REST بـ Express و TypeScript مع حفظ الملاحظات في ملف.

في وضع التطوير توجّه الواجهة طلبات `/api/*` إلى الخادم، لذلك تشغّل الاثنين
معاً وتتعامل مع عنوان واحد.

## الميزات

- إنشاء الملاحظات وتعديلها وحذفها (عنوان + نص اختياري).
- بحث في القائمة الظاهرة، بما في ذلك اختلافات الإملاء العربية (الألف، التشكيل،
  الهمزة، الياء/الكاف الفارسية، الأرقام العربية الشرقية) والتشكيل اللاتيني.
- إخراج الملاحظات المطابقة كـ JSON أو Markdown من الواجهة، أو كل الملاحظات من
  واجهة البرمجة.
- لغة الواجهة تتبع المتصفح: العربية مع اتجاه من اليمين لليسار عندما يفضّل
  المتصفح `ar`، وإلا الإنجليزية مع اتجاه من اليسار لليمين.
- حفظ على القرص يبقى بعد إعادة تشغيل الواجهة البرمجية، مع كتابة ذرية ورفض
  الكتابة إذا كان ملف البيانات تالفاً.
- تنبيه عند وجود تغييرات غير محفوظة، تأكيد قبل الحذف، وإعادة محاولة عند فشل
  التحميل.

## المتطلبات

- Node.js `>= 20` (طُوّر على Node 22)
- npm `>= 10`

## البدء

```bash
npm install        # تثبيت اعتماديات كل مساحات العمل
npm run dev        # تشغيل الواجهة البرمجية (:3001) والعميل (:5173) معاً
```

ثم افتح http://localhost:5173 وأنشئ ملاحظة.

للبناء الإنتاجي تخدم الواجهة البرمجية أيضاً الواجهة المجمّعة:

```bash
npm run build
npm start          # http://localhost:3001 (واجهة برمجة + واجهة مستخدم)
```

| الأمر | الوصف |
| --- | --- |
| `npm run dev` | تشغيل العميل والخادم معاً مع إعادة التحميل الحي |
| `npm run dev:server` | تشغيل واجهة Express فقط على المنفذ `3001` |

| `npm run build` | بناء الخادم والعميل للإنتاج |
| `npm start` | تقديم الواجهة البرمجية والواجهة المبنية على المنفذ `3001` |

## متغيرات البيئة

| المتغير | الافتراضي | المكان | الوصف |
| --- | --- | --- | --- |
| `PORT` | `3001` | الخادم | منفذ الاستماع HTTP |
| `HOST` | `0.0.0.0` | الخادم | عنوان الربط HTTP |
| `NOTES_DATA_FILE` | `server/data/notes.json` | الخادم | ملف JSON لحفظ الملاحظات |
| `VITE_API_TARGET` | `http://127.0.0.1:3001` | العميل (Vite) | عنوان الواجهة البرمجية لوكيل `/api` |

مجلد البيانات مستثنى من Git. الملف غير الموجود يُعامل كمخزن فارغ ويُنشأ عند
أول كتابة ناجحة.

## شكل الملاحظة

كل ملاحظة كائن JSON:

| الحقل | النوع | القواعد |
| --- | --- | --- |
| `id` | نص | UUID يولّده الخادم |
| `title` | نص | مطلوب، بعد القص، من 1 إلى 200 حرف |
| `body` | نص | اختياري، بعد القص، حتى 8000 حرف. القيم غير النصية تصبح `""` |
| `createdAt` | نص | طابع زمني UTC بصيغة ISO-8601 |
| `updatedAt` | نص | طابع زمني UTC بصيغة ISO-8601. يختلف عن `createdAt` بعد التعديل |

تُعرض الملاحظات من الأحدث حسب `updatedAt`.

## واجهة البرمجة (ملخص)

التفاصيل الكاملة للطلبات والاستجابات في [`docs/api.ar.md`](docs/api.ar.md).

| الطريقة | المسار | الوصف |
| --- | --- | --- |
| `GET` | `/api/health` | فحص الصحة (`persist`: `ok` أو `degraded` أو `unavailable`) |
| `GET` | `/api/notes` | قائمة الملاحظات (الأحدث أولاً) |
| `GET` | `/api/notes/export` | تنزيل كل الملاحظات (`?format=json` أو `md`) |
| `GET` | `/api/notes/:id` | جلب ملاحظة واحدة |
| `POST` | `/api/notes` | إنشاء ملاحظة `{ title, body? }` |
| `PUT` | `/api/notes/:id` | تحديث جزئي `{ title?, body? }` |
| `DELETE` | `/api/notes/:id` | حذف ملاحظة |

أمثلة سريعة:

```bash
curl -s http://127.0.0.1:3001/api/health
curl -s -X POST http://127.0.0.1:3001/api/notes \
  -H 'Content-Type: application/json' \
  -d '{"title":"مرحبا","body":"أول ملاحظة"}'
curl -s http://127.0.0.1:3001/api/notes/export?format=md -o notes.md
```

العنوان محدود بـ 200 حرف والنص بـ 8000. JSON غير الصالح والعناوين الناقصة
ترجع `400`. `PUT` تحديث جزئي: الحقول المحذوفة تبقي قيمها الحالية. المسارات
غير المعروفة تحت `/api` ترجع JSON `404`. فشل الكتابة على القرص يرجع `503`
ويتراجع عن التغيير في الذاكرة.

## الحفظ على القرص

تُحفظ الملاحظات في `server/data/notes.json` (يمكن تجاوزه بـ `NOTES_DATA_FILE`)
حتى تبقى بعد إعادة تشغيل الواجهة البرمجية.

- الكتابة ذرية (ملف مؤقت ثم إعادة تسمية).
- مراقب ملفات التطوير يتجاهل `server/data` حتى لا تعيد حفظ ملاحظة تشغيل الخادم.
- الملف التالف أو غير القابل للقراءة لا يُستبدل أبداً.
- عندها ترجع قائمة الملاحظات `503` بدل قائمة فارغة (`persist: unavailable`).
- السجلات غير الصالحة (عناوين فارغة، حقول أطول من الحد، تواريخ سيئة، أو معرفات
  مكررة) تُتخطى: الصحة تصبح `degraded`، الملاحظات الصالحة ما زالت تُعرض،
  والكتابة ترجع `503` حتى يُصلح الملف.
- الطوابع الزمنية المحمّلة تُحوَّل إلى UTC ISO-8601 حتى يبقى الترتيب ووسم
  «معدّلة» صحيحين مع الصيغ المختلطة.

## واجهة المستخدم

- اللغة والاتجاه يتبعان المتصفح: العربية (`ar` و `ar-*`) باتجاه من اليمين
  لليسار؛ غير ذلك الإنجليزية من اليسار لليمين.
- حقلا العنوان والنص يستخدمان `dir="auto"` حتى تبقى الملاحظات المختلطة
  مقروءة.
- البحث يطابق العناوين والنصوص بعد توحيد أشكال الألف والتشكيل والهمزة على
  الواو/الياء والياء/الكاف الفارسية والأرقام العربية الشرقية والفارسية
  والتشكيل اللاتيني والمسافات الزائدة.
- أزرار الإخراج تنزّل الملاحظات **المطابقة حالياً** (بعد فلتر البحث) وليس
  بالضرورة المخزن كاملاً. إخراج واجهة البرمجة يضم كل الملاحظات دائماً.
- الحذف يطلب تأكيداً. مغادرة نموذج فيه تغييرات تسأل قبل التجاهل. Escape يلغي
  التعديل الجاري.
- إذا تعذر الوصول إلى الواجهة البرمجية عند التحميل الأول، تعيد الواجهة
  المحاولة ثم تعرض زر **إعادة المحاولة**.

## هيكل المشروع

```
.
├── client/                 # واجهة React + Vite
│   └── src/
│       ├── App.tsx         # واجهة الملاحظات (إنشاء، تعديل، بحث، إخراج)
│       ├── api.ts          # عميل REST والتحقق من الاستجابة
│       ├── i18n.ts         # النصوص العربية/الإنجليزية وتوحيد البحث
│       └── exportNotes.ts  # تنزيل JSON/Markdown من المتصفح
├── server/                 # واجهة Express + TypeScript
│   └── src/
│       ├── index.ts        # الاستماع، مسار الحفظ، الواجهة الثابتة الاختيارية
│       ├── app.ts          # مسارات HTTP وتعيين الأخطاء
│       ├── notesStore.ts   # المخزن في الذاكرة + حفظ JSON
│       └── exportNotes.ts  # إخراج JSON/Markdown من الخادم
├── docs/                   # توثيق إضافي
├── eslint.config.js        # إعداد ESLint المشترك
└── package.json            # مساحات عمل npm والأوامر العليا
```
