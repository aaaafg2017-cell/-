# تطبيق الملاحظات

[English](README.md)

تطبيق ملاحظات صغير كامل المكدس: واجهة أمامية بصفحة واحدة مبنية بـ React و Vite
تتحدث مع واجهة برمجية (API) بـ Express و TypeScript تحفظ الملاحظات في ملف JSON.
التطبيق بسيط عمداً، لكنه يعالج التفاصيل غير البراقة — التحقق من المدخلات،
والكتابة الذرية إلى القرص، والتعافي من ملف بيانات تالف، والتعريب، وحالات الخطأ —
ليصلح كنقطة انطلاق واقعية لا كمثال تعليمي فقط.

- **`client/`** — تطبيق صفحة واحدة بـ React 18 و Vite و TypeScript.
- **`server/`** — واجهة REST بـ Express 4 و TypeScript مع حفظ الملاحظات في ملف.

أثناء التطوير يمرّر العميل الطلبات `‎/api/*` إلى الخادم، لذلك تُشغّل الطرفين معاً
وتتعامل مع عنوان واحد فقط.

## المزايا

- إنشاء الملاحظات وتعديلها وحذفها، مرتبة من الأحدث إلى الأقدم، مع إشارة
  «معدّلة».
- بحث في العناوين والنصوص يتسامح مع اختلافات الألف والهمزة والتشكيل، والياء
  والكاف الفارسيتين، والأرقام العربية المشرقية، والحروف اللاتينية المشكّلة،
  والمسافات الزائدة.
- إخراج الملاحظات الظاهرة حالياً بصيغة JSON أو Markdown، من الواجهة أو من الـ API.
- واجهة بالعربية والإنجليزية تُختار من لغة المتصفح، مع تخطيط كامل من اليمين
  إلى اليسار.
- حفظ الملاحظات على القرص عبر كتابة ذرية، مع رفض الكتابة فوق ملف بيانات تعذّرت
  قراءته بالكامل.
- حماية من فقدان العمل: تأكيد قبل تجاهل التعديلات، وتأكيد قبل الحذف، وإعادة
  محاولة عند الإقلاع، ورسائل خطأ مترجمة.

## المتطلبات

- Node.js بإصدار `>= 20` (طُوّر على Node 22)
- npm بإصدار `>= 10`

## البدء السريع

```bash
npm install        # تثبيت اعتماديات جميع مساحات العمل
npm run dev        # تشغيل الـ API على 3001 والعميل على 5173 معاً
```

ثم افتح http://localhost:5173 وأنشئ ملاحظة.

للبناء للإنتاج، يقوم الخادم أيضاً بتقديم واجهة العميل المبنية:

```bash
npm run build
npm start          # http://localhost:3001 (الـ API والواجهة معاً)
```

## الأوامر الشائعة

| الأمر | الوصف |
| --- | --- |
| `npm run dev` | تشغيل العميل والخادم معاً مع إعادة التحميل التلقائي |
| `npm run dev:server` | تشغيل واجهة Express فقط على المنفذ `3001` |
| `npm run dev:client` | تشغيل خادم Vite التطويري فقط على المنفذ `5173` |
| `npm test` | تشغيل جميع مجموعات الاختبارات (Vitest) |
| `npm run typecheck` | فحص الأنواع في كل مساحات العمل |
| `npm run lint` | فحص الشيفرة بالكامل عبر ESLint |
| `npm run build` | بناء الخادم والعميل للإنتاج |
| `npm start` | تقديم الـ API والواجهة المبنية على المنفذ `3001` |

## الإعدادات

| المتغير | القيمة الافتراضية | الغرض |
| --- | --- | --- |
| `PORT` | `3001` | منفذ استماع الـ API |
| `HOST` | `0.0.0.0` | عنوان استماع الـ API |
| `NOTES_DATA_FILE` | `server/data/notes.json` | مسار ملف حفظ الملاحظات |
| `VITE_API_TARGET` | `http://127.0.0.1:3001` | وجهة التمرير التي يستخدمها العميل في التطوير والمعاينة |

## الواجهة البرمجية

| الطريقة | المسار | الوصف |
| --- | --- | --- |
| `GET` | `/api/health` | فحص الحالة (`persist`: `ok` أو `degraded` أو `unavailable`) |
| `GET` | `/api/notes` | سرد الملاحظات (الأحدث أولاً) |
| `GET` | `/api/notes/export` | تنزيل كل الملاحظات (`?format=json` أو `md`) |
| `GET` | `/api/notes/:id` | جلب ملاحظة واحدة |
| `POST` | `/api/notes` | إنشاء ملاحظة `{ title, body? }` |
| `PUT` | `/api/notes/:id` | تحديث جزئي لملاحظة `{ title?, body? }` |
| `DELETE` | `/api/notes/:id` | حذف ملاحظة |

الحد الأقصى للعنوان 200 حرف وللنص 8000 حرف، و`PUT` يُبقي الحقول التي لم تُرسلها
كما هي. الأخطاء تُعاد دائماً بصيغة JSON، والمسارات غير المعروفة تحت `‎/api` تُعيد
`404` بصيغة JSON. يشرح [مرجع الـ API](docs/api.md) كل حمولة ورمز حالة وحالة حفظ.

## البيانات والمتانة

تُحفظ الملاحظات في `server/data/notes.json` (يمكن تغيير المسار عبر
`NOTES_DATA_FILE`) لتبقى بعد إعادة تشغيل الخادم. تُكتب البيانات إلى ملف مؤقت ثم
يُعاد تسميته فوق الملف الأصلي، وإذا فشلت الكتابة يُتراجع عن التغيير في الذاكرة.
وإذا كان ملف البيانات تالفاً أو يحتوي سجلات غير صالحة، يواصل الخادم تقديم ما
استطاع قراءته، ويُبلغ عن `degraded` أو `unavailable` في `/api/health`، ويُعيد
`503` لعمليات الكتابة بدلاً من الكتابة فوق الملف.
